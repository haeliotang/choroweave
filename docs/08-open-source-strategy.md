## 0. 一页结论

1. **定位不是平台，是"世界的 DNS + HTTP"。** 成功不取决于我们托管了多少世界，而取决于**别人的**世界与节点用 SHP 连起来了多少（[`00`](00-executive-summary.md) §5）。因此一切设计以"可被第三方实现"为第一原则。
2. **协议永久免费，参考实现 Apache-2.0，护城河是一致性套件。** 与 glTF/Khronos 的教训一致：协议类项目的壁垒不是代码，而是"可验证的一致性 + 生态采用"（02 ADR-12）。
3. **不做 UGC 抽成、不做中心化托管垄断、不做付费认证垄断。** Rec Room（UGC 抽成 30¢ vs 第一方 70¢、付费率 <2%）与 Spatial（托管成本公开信）已经证明这两条路都通向死亡【官方 + 媒体转述】。
4. **可持续收入只来自"服务"，不来自"许可"**：托管节点服务、企业私有部署、支持合同、培训、捐赠/赞助。协议、SDK、一致性套件、迁移工具永久免费且可自托管。
5. **标准路线三段式**：`CHW_` 自研（P0）→ OMI Stage 1/W3C CG（P1 起提交）→ MSF "Web of Worlds"/Khronos glTF（P2–P4）。对齐 X3D 4.1 WoW 的 **Anchor（3D 超链接）/Inline（外部场景）** 语义，不另造空间语言。
6. **冷启动用"展陈空间"获客、"活动巡游"留存**（与 `00` §5 一致）：3 个 showcase 世界（像素天台 / 悬崖酒馆 / 地牢解谜）+ 10 位创作者 + 日本先行社区验证 + GitHub/Discord 双周节奏。

## 1. 定位、叙事与差异化

### 1.1 一句话与三条信息

> **choroweave 是空间时代的"HTML 编译器 + HTTP + 浏览器"**：把意图编译成可玩世界包，用 SHP 把个人节点上的世界像网页一样互相链接。

对外沟通只用三条信息（30 秒版）：
1. **世界像网页一样可寻址**：一个 URL = 一个世界，可链接、可缓存、可自托管。
2. **编译而不是手搓**：一句话 → 骨架优先的确定性装配 → 可验证的世界包（不是"AI 生成一段视频"）。
3. **不是我们的平台**：协议与参考实现开源，你的世界在你的服务器上；我们不抽成、不扣内容。

**禁区词**（禁用为主叙事）：元宇宙、虚拟地产、链上资产、脑机接口、世界模型取代引擎。理由：2024–2026 的媒体叙事已把这些词变成负资产（Horizon Worlds 关停风波、Rec Room 停服、Decentraland MANA 跌幅 >98%【第三方】）。

### 1.2 差异化（不是"更好的 X"，是"X 之间的连接"）

| 对手/参照 | 它是什么 | 我们不做什么 | 我们的位置 |
|---|---|---|---|
| Roblox / Fortnite | 封闭 UGC 平台（DAU 1.38 亿 / MAU 1.1–1.2 亿）【官方 + 第三方】 | 不做"更好的 Roblox" | 做**跨平台可携带**：World Bundle 可导出 glTF/VRM、可外部链接 |
| Astrocade | 消费级 AI 游戏平台（5M MAU、未公布变现）【第三方】 | 不做信息流式消费平台 | 做**可自托管 + 可互联**的编译器与节点 |
| Bitmagic GDK | Agent-first 游戏 SDK（2026-08-27）【官方】 | 不做"另一个 agent 工具链" | 补**世界间寻址/门户/身份**（Bitmagic 世界托管在自家服务器） |
| Marble / World Labs | 文本/图 → 持久 3D 资产（$0.12–2.48/世界）【第三方】 | 不做世界模型 | 做**生成之后的落地层**：可寻址、可进入、可组合 |
| VRChat | 中心化社交 VR（MAU >100 万、25 万+ 社区）【官方 + 第三方】 | 不做通用社交平台 | 做**跨运营方的传送门**（VRChat 的门锁在中心服务器） |
| Hyperfy / OMI / Hubs CE | 自托管世界/互操作词汇/社区客户端 | 不 fork（Hyperfy GPL-3.0、Hubs Elixir 重栈） | 做**孤岛之间的寻址层**，第一个实现互操作 |

> 判断依据：平台的生态位已被占满，生成层已被资本定价（World Labs 融资约 $12.3 亿【第三方/媒体】），**协议层仍空**（[`research/04`](research/04-products-market-prior-art.md) §5 结论 1）。

### 1.3 成功定义（不是 MAU）

| 维度 | 指标 | P1 | P2 | P3 | P4 |
|---|---|---|---|---|---|
| 协议采用 | 通过 conformance 的第三方运行时 | 1（自研） | 1 | 2 | ≥3 |
| 网络规模 | 公开世界 / 第三方节点 | 3 / 0 | 30 / 3 | 100 / 10 | 500 / 50 |
| 网络密度 | 跨域门户链接数（每周） | — | 50 | 500 | 5,000 |
| 可携带性 | 成功导出到第三方引擎的世界数 | 10（内部） | 100 | 1,000 | 10,000 |

> 口径与 [`05`](05-roadmap.md) §5.1、`00` §8 一致；表中目标值为工程规划（C）；"跨域门户链接数"是新增观察指标（P2 起统计，需节点 opt-in 上报聚合值）。

## 2. 仓库与包边界

### 2.1 仓库拓扑

| 仓库 | 内容 | 许可证 | 可见性 | 发布 |
|---|---|---|---|---|
| `choroweave/choroweave` | **主 monorepo**：`@choroweave/*` 全部包 + 文档 | Apache-2.0（文档 CC-BY-4.0） | 公开 | npm（`@choroweave/*`）、Docker |
| `choroweave/spec` | SHP/WSP 规范文本、conformance 用例、`CHW_*` 扩展定义、OMI/MSF 映射文档 | CC-BY-4.0 | 公开 | 规范版本 tag（v0.1/v0.5/v1.0） |
| `choroweave/weave-check` | 一致性套件 CLI（可独立安装） | Apache-2.0 | 公开 | npm + 静态二进制 |
| `choroweave/examples` | `pixel-rooftop`、`cliff-tavern`、`dungeon-puzzle` 及模板/套件 | 示例世界 CC0/CC-BY；套件 CC-BY | 公开 | 随 release tag |
| `choroweave/registry` | 可选的世界索引/发现协议与参考实现（P3） | Apache-2.0 | 公开 | 独立服务镜像 |
| `choroweave/hosted` | 托管服务的**运营层**（计费、多租户、审计面板、账单） | 默认私有 | 私有 | 不作为开源交付物 |

**开源边界原则**：
1. **协议、编译器、运行时、节点、校验套件、迁移工具全部开源**，且可完整自托管（无"开源版功能阉割"）。
2. 仅"托管服务的运营层"（计费/多租户/审计面板）可私有；但其**数据导出与迁移 API 必须公开文档化**，保证用户可无痛搬走（反锁定承诺，见 §7.5）。
3. 不做"开放核心（open core）"式的功能钓鱼：托管服务卖的是**运维、SLA、合规与支持**，不是许可证。

### 2.2 包与依赖方向（战略视图）

| 包 | 职责 | 依赖方向 | 维护者 |
|---|---|---|---|
| `@choroweave/dsl` | Spatial-DSL AST / JSON Schema / 校验 | 无内部依赖 | CL |
| `@choroweave/compiler` | 编译管线 + CLI（`build/preview/publish/eval`） | dsl、assembler、provider-*、check | CL |
| `@choroweave/assembler` | glb 装配、碰撞体、LOD、行为图生成 | dsl | CL/RL |
| `@choroweave/provider-trellis` / `-hunyuan` / `-kit` | 资产生成 provider（可插拔） | 无内部依赖（协议隔离） | CL |
| `@choroweave/protocol` | SHP/WSP 类型与编解码 | 无内部依赖 | SL |
| `@choroweave/runtime` | Babylon 封装、行为图宿主、门户切换、输入抽象 | protocol、dsl（类型） | RL |
| `@choroweave/node` | 静态托管 + 房间服务 + 发现 + 鉴权 | protocol、runtime（仅类型） | SL |
| `@choroweave/check` | 一致性套件（`weave-check`） | dsl、protocol | SL |

**硬规则**：`protocol` 不依赖任何上层；`dsl` 不依赖运行时；provider 包不得被 `runtime` 反向依赖；所有跨包类型通过 `protocol`/`dsl` 的公开 schema 传递。依赖方向若被破坏，CI 失败。

### 2.3 与 [`03-architecture.md`](03-architecture.md) 的一致性

本表是**战略视图**；最终目录结构、包划分与里程碑映射以 **03 §11 为单一事实源**。若 03 定稿后与本文不一致，本文在 48 小时内对齐并在 §12 变更记录中登记，不回改 03。

### 2.4 与 tacitweave 的边界

- 独立仓库、独立发布节奏（ADR-01）；**不共享代码库**。
- 契约：`schemas/implicit-spatial-spec.schema.json`（ISS）版本化；choroweave P1 用 **mock ISS**，P2 再接入真实 ISS（与 `00` §10 一致）。
- 任何 ISS 字段变更需双方 RFC 互认；choroweave 不得依赖 tacitweave 的运行时。

## 3. 贡献流程、RFC 与版本策略

### 3.1 贡献者阶梯

| 级别 | 条件 | 权利 | 义务 |
|---|---|---|---|
| **用户** | 使用/部署 | 提 issue | 遵守行为准则 |
| **贡献者** | ≥1 个被合并 PR | 提 PR | DCO 签署 |
| **审查者** | ≥5 个被合并 PR 且 1 个领域 | 审查 PR | 7 天内响应分配 |
| **维护者** | 持续 6 个月贡献 + 现有维护者提名 | 合并权、RFC 投票 | 季度维护报告 |
| **技术委员会** | 见 §8 | 规范/架构决策 | 冲突裁决 |

### 3.2 PR 要求

- 所有 commit 需 **DCO** 签署（`Signed-off-by`），不引入 CLA（降低门槛；商标与规范版权由项目持有，见 §8.4）。
- 必过：单元/集成测试、`weave-check` 自检、license 扫描、SBOM diff、格式化、文档更新。
- 变更需 **changeset**（版本与变更说明）；影响协议/世界的变更必须附 conformance 用例。
- 生成/资产相关 PR 必须附 `provenance` 与许可声明；示例世界必须通过预算校验。

### 3.3 RFC 流程（规范类在 `choroweave/spec`，实现类在 monorepo `rfcs/`——目录见 [`03`](03-architecture.md) §11.1）

| 阶段 | 内容 | 时限 |
|---|---|---|
| 0 提案 | issue 模板：问题/动机/兼容性/替代方案/安全影响 | — |
| 1 草稿 | `rfcs/NNNN-title.md`，含 schema 变更与迁移路径 | 2 周评论 |
| 2 最后评论 | 进入 lazy consensus | 7 天 |
| 3 接受/拒绝 | 维护者 + 技术委员会（规范类）投票 | 7 天内公布 |
| 4 实现 | 参考实现 + conformance 用例 | 随 release |

**触发 RFC 的条件**：`world.json`/SHP/WSP 字段增删改；`CHW_*` 扩展语义变更；一致性套件用例语义变更；许可证/治理变更。**不触发**：内部重构、CLI 输出格式（但需 changeset）。

### 3.4 版本策略

| 对象 | 版本方案 | 兼容承诺 |
|---|---|---|
| npm 包 | SemVer；`0.x` 期间 minor 可破坏（明确告知） | 1.0 后破坏性变更需 major + 12 个月并行 |
| SHP/WSP 规范 | `v0.1`（P0）→ `v0.5`（P2）→ `v1.0`（P4） | 规范 v1.0 后：废弃字段保留 ≥2 个 minor（≥12 个月） |
| `CHW_*` 扩展 | 独立 `version` 字段；未知扩展**必须优雅忽略** | 只增不改；破坏性语义用新扩展名 |
| 世界包 | `world.json.engineVersion` + 资产内容哈希 | 提供"旧包 → 新包"迁移 CLI；不支持自动升级的标注 |

**兼容矩阵**：`weave-check` 在每个规范版本发布时生成兼容矩阵（node/runtime/spec 版本 × 通过状态），随 release 发布。

### 3.5 发布节奏

- **trunk-based**：`main` 始终可发布；长期分支必须命名 `release/x.y` 且由维护者创建。
- **月度 minor**（每月第一个周二），**季度 release train**（含规范/示例/文档整体版本）；安全修复随时 hotfix。
- 每个 release：SBOM（CycloneDX）+ 产物 SHA-256 + 许可证报告 + conformance 结果 + 变更日志（面向用户与面向实现者两版）。

## 4. 标准路线：`CHW_` → OMI → MSF/Khronos

### 4.1 三段式

| 阶段 | 动作 | 对象 | 时间 | 成功判据 |
|---|---|---|---|---|
| 1 | `CHW_portal`/`world.json` 自研并 shipped（P0–P2） | 自有生态 | M0–M12 | 第三方节点 ≥3 使用同一字段 |
| 2 | 提交 **OMI Stage 1**（W3C Metaverse Interoperability CG；需 W3C CLA + JSON Schema + 至少一个实现 + 样例资产） | OMI / W3C CG | P1 起提交，P3 前进入 Stage 1 | PR 合并、Stage 1 状态公示 |
| 3 | 映射文档提交 **MSF "Web of Worlds"** 与 **Khronos glTF**（对齐 glTF 2.1 外部引用语义） | MSF / Khronos | P3–P4 | 被引用/进入工作组议程 |

> 依据：OMI 现无 portal 扩展（`OMI_link` 已归档）、`OMI_spawn_point` 仍 Stage 1【官方】；MSF 2026 提出 Web of Worlds 并配套 X3D 4.1 WoW Profile（Anchor/Inline）【标准组织】；glTF 2.1 的外部引用/多文件组合是"跨服务器场景"的天然承载点（[`research/03`](research/03-runtime-standards.md) §3.1）。**不等待标准**（OMI 走完 Stage 3–5 至少 1–2 年），但**始终对齐语义**。

### 4.2 映射表（提交标准的底稿）

| choroweave 概念 | X3D 4.1 WoW Profile | OMI | 备注 |
|---|---|---|---|
| 世界标识（HTTPS URL → `world.json`） | 可寻址场景（Inline 目标） | `OMI_spawn_point` 语义复用 | 主名是 URL，`weave://` 仅别名 |
| `CHW_portal`（门户节点） | **Anchor（3D 超链接）** | 无（`OMI_link` 已归档） | 补"进入握手/信任/预取/回滚" |
| World Bundle 外部场景引用 | **Inline（外部场景）** | — | 与 glTF 2.1 外部引用对齐 |
| `CHW_collider` | — | `OMI_physics_shape` 语义子集 | 不依赖（KHR_physics 仍 Review Draft） |
| `CHW_logic`（能力声明） | — | — | 节点能力协商用 |
| `CHW_avatar`（P2） | — | — | 先 glTF 人形，P2 评估 VRM |
| 进入握手（arrive / session token） | —（WoW 未定义） | — | choroweave 的补白，也是提交重点 |

### 4.3 提交物清单

1. `CHW_portal` 的 JSON Schema + 一致性用例（≥10 条）+ 参考实现报告（Babylon + 第三方查看器）。
2. 与 X3D Anchor/Inline 的字段级映射文档（含差异说明与迁移建议）。
3. "进入握手"的最小规范草案（安全模型、失败语义、隐私等级）。
4. ISMAR 2026《The Web of Worlds: Towards A Referential Architecture for Open Spatial Worlds》的引用与工程化差异说明（**不宣称首创**，见 [`research/04`](research/04-products-market-prior-art.md) §3.7）。
5. conformance 报告（≥2 个独立实现通过）。

### 4.4 不做什么

- 不另造一套空间语言（SHP 是 profile，不是新格式）。
- 不把 DSL 提成公开标准（DSL 是编译器内部 IR，02 ADR-02/03）；公开契约是 World Bundle + `world.json`。
- 不承诺标准时间表（OMI/Khronos 节奏不由我们控制）；对外只承诺"提交与实现"。

## 5. 社区冷启动

### 5.1 三个 showcase 世界（与 `00` §11 选题一致）

| 世界 | 类型 | 作用 | 对应楔子 | 成功信号 |
|---|---|---|---|---|
| **像素天台**（`pixel-rooftop`） | 个人空间 + 收音机 + 门 | 旗舰 demo：一句话→进入→互动→串门 | P1 展陈/个人空间 | 演示视频 1 万次观看；10 位创作者复刻 |
| **悬崖酒馆**（`cliff-tavern`） | 活动场地（8–20 人） | P2 跨社区活动巡游的"活动节点" | P2 巡游 | 每月 ≥1 场真实活动；跨社区参与 ≥30% |
| **地牢解谜**（`dungeon-puzzle`） | L0 行为图玩法 + 多门路线 | 证明"无脚本也能有玩法"；开发者模板 | 开发者工具线 | 被 3 个第三方世界复用为模板 |

三个世界全部 CC0/CC-BY 发布，源码（DSL + manifest + 套件）公开，可被 fork 成自己的世界。

### 5.2 创作者计划（首批 10 位）

| 给什么 | 要什么 | 不做什么 |
|---|---|---|
| 早期编译器访问、1:1 支持、showcase 首页位、托管额度、创作基金（小额，估算 $500–2,000/人，C） | 每月 ≥1 个公开世界；允许署名展示；反馈 bug | **不排他**、不要求独家内容、不签内容买断、不抽成 |

选择标准：已有 3D 资产（Blender/GLB/Marble 输出）的独立艺术家、小工作室、社区组织者（对应 [`06`](06-mvp-spec.md) persona A/B）。**优先日本市场**：VRChat 官网访问 37% 来自日本【第三方】、日本 IP 活动生态成熟；但不做"日本专属"叙事。

### 5.3 渠道与节奏

- **GitHub**：主阵地（issue/PR/RFC）；每两周一次 "demo day"（线上，30 分钟：一个世界 + 一个技术进展）。
- **Discord**：分频道（`#showcase`/`#help`/`#dev`/`#standards`）；不做"客服式"承诺，鼓励互帮。
- **文档站**：快速开始（30 分钟）+ 编译器手册 + 节点运维手册 + 规范。
- **发布节奏**：每个门（G0–G4）一次对外 demo + 一篇技术博客；不追热点。

### 5.4 首发叙事（一句话 → 三分钟）

- 一句话：**"世界之间的 DNS + HTTP。"**
- 三分钟结构：① 问题（作品只能看不能走；世界被锁在平台里；平台会关）；② 演示（一句话 → 走进 → 推门到另一个世界）；③ 主张（协议开源、世界自托管、可携带；我们不抽成）。
- 素材纪律：所有数字标注证据等级与日期；不引用"未能核实"的数据（[`research/04`](research/04-products-market-prior-art.md) §6.1）；不宣称"首创空间超链接"，明确引用 MSF WoW 与 ISMAR 2026。

### 5.5 冷启动 KPI（与 05 一致）

`W1R` 次周回访率（P2 ≥15%、P3 ≥25%、P4 ≥35%）、公开世界/第三方节点（P3 100/10、P4 500/50）、跨域门户链接数、创作者计划留存（10 位中 ≥7 位在 6 个月后仍持续发布）。

## 7. 可持续模式（商业模式）

### 7.1 明确不做（每条都有尸检报告）

| 不做 | 证据 | 后果 |
|---|---|---|
| ❌ UGC 交易抽成为主收入 | Rec Room：第一方道具留 ~70¢/$、UGC 道具仅留 ~30¢/$、付费率 <2%，UGC 越成功越亏【媒体转述官方数据】 | 规模越大越亏 |
| ❌ 中心化托管垄断 | Mozilla Hubs 2024-05-31 关停、Spatial 2025-07-27 关闭创作者平台（托管成本）【官方】 | 成本由单一主体承担，预算收缩先被砍 |
| ❌ 付费"官方认证"/许可收费 | 协议采用依赖无条件可验证；收费认证会鼓励分裂 | 生态碎片化 |
| ❌ 链上资产/代币/土地 | Decentraland MANA 跌幅 >98%、unity-renderer 归档【第三方/GitHub API】 | 金融化替代产品迭代 |
| ❌ 卖用户数据/广告 | 与默认私密、未成年人保护冲突 | 合规与信任崩塌 |

### 7.2 四条收入线

| 收入线 | 客户 | 内容 | 定价示意（估算，C） | 启动 |
|---|---|---|---|---|
| **托管节点服务** | 不会运维的创作者/社区 | 一键托管（含 TLS/域名/备份/监控/升级）、可选自定义域 | **$9–29/世界/月**（含 20 GB 出口 + 1 个房间）；企业档 $99–299/月 | P2 末试点，P3 正式 |
| **企业私有部署** | 品牌/学校/展馆/企业 | 私有节点 + SSO + 审计 + 离线资产管线 + 培训 | **$15k–80k/项目**（一次性）+ 年支持 20% | P3 |
| **支持合同 / SLA** | 有线上活动的组织、托管商 | 响应时限、版本支持、迁移协助、安全通告 | **$5k–50k/年** | P3 |
| **培训与内容服务** | 团队/机构 | 工作坊、模板定制、showcase 制作 | **$2k–15k/项目** | P3–P4 |
| **捐赠/赞助** | 社区/基金会/企业赞助 | 无对价或品牌露出 | 任意 | P1 起（GitHub Sponsors/Open Collective） |

> 定价与 [`07`](07-risks-compliance.md) §3 成本假设一致：单世界基础托管成本 $1.3–6.5/月（10–1000 世界规模，估算），因此 $9–29/月 的托管服务具备毛利空间；但**不追求**靠托管规模盈利（避免重演 Hubs/Spatial 的固定成本陷阱）。

### 7.3 收入与成本的关系（示意，估算）

- 托管服务：单世界月成本 $1.3–6.5（含房间服分摊），定价 $9–29 → 毛利率约 55%–80%（不含人力与客服）。
- 企业部署：一次性 $15k–80k，交付人力约 2–6 人周 → 毛利取决于定制深度；**不做无边界定制**。
- 支持合同：按 15%–25% 年费，覆盖 1–2 名维护者的部分时间。
- **盈亏平衡示意**：3 人小队月成本 $45k–65k（[`05`](05-roadmap.md) §4.1），若托管 300 个世界 × $19/月 ≈ $5.7k/月，仅覆盖 10%；因此**早期以捐赠/资助 + 企业部署为主**，托管服务是长期基本盘而非早期救命稻草。不得把"托管收入"写进早期财务假设。

### 7.4 开源与商业的边界（反锁定承诺）

1. 协议、SDK、节点、校验、迁移工具永久免费且可自托管；**不因未付费而限制核心功能**。
2. 托管服务提供**一键导出**（World Bundle + 身份 + 日志）与**迁移到自托管节点**的脚本；导出 API 文档公开。
3. 不使用"数据 hostages"（世界包格式是开源 glTF + JSON）；不限制用户把世界托管到别处。
4. 官方不参与"世界内容"的交易抽成；若第三方托管商提供增值服务，由其自行定价。

### 7.5 治理与商业的隔离

商业实体（托管/支持）与开源项目（协议/治理）分离：商业决策不得改变协议语义；涉及协议变更走 §3.3 RFC，商业方没有额外否决权。治理路线见 §8。

## 8. 治理

### 8.1 三阶段

| 阶段 | 时间 | 决策结构 | 触发升级条件 |
|---|---|---|---|
| **BDFL** | P0–P2（M0–M12） | 项目负责人（PL）最终裁决；技术委员会（3 人：TL/SL/CL）建议 | 外部维护者 ≥5 人，或第三方节点 ≥10 |
| **委员会** | P3（M12–M18） | 技术委员会 5–7 人（含 ≥2 名外部维护者），规范变更需 2/3 多数 | 委员会稳定运转 ≥6 个月；出现 ≥2 个商业托管方 |
| **基金会** | P4 起（M18+） | 独立基金会/挂靠现有组织（候选：MSF 成员路径、W3C CG、软件自由保护协会类）；章程、商标、资金托管 | G4 前完成章程签署 |

### 8.2 决策权

| 事项 | BDFL 期 | 委员会期 | 基金会期 |
|---|---|---|---|
| 代码合并 | 维护者 | 维护者 | 维护者 |
| 规范语义（SHP/WSP/`CHW_*`） | PL + 技术委员会 | 技术委员会 2/3 | 技术委员会 + 社区评议 |
| 商标/品牌使用 | PL | 委员会 | 基金会 |
| 资金/资助 | PL | 委员会 | 基金会理事会 |
| 行为准则/冲突 | PL | 委员会（含外部代表） | 基金会 |
| 商业服务定价 | 商业实体 | 商业实体（协议无关） | 商业实体（需披露） |

### 8.3 行为准则与安全响应

- 采用 Contributor Covenant 类行为准则；违规处理由委员会执行，申诉路径公开。
- `security.txt` + 私有披露渠道；安全公告与 CVE（如需要）流程见 [`07`](07-risks-compliance.md) §10。
- 透明度：季度社区报告（贡献者数、PR 响应时长、举报/处置数、资金去向）。

### 8.4 商标与 conformance（不收费）

- 名称 "choroweave / 原质之织"、logo 由项目/基金会持有；第三方可声明"兼容 SHP vX"，但不得暗示官方背书。
- **conformance 认证免费且自测即可**（跑 `weave-check` 并公开报告）；不做付费认证、不做"官方认证"门槛。这是协议采用的必要条件（与 §7.1 一致）。

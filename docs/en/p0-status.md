## How to reproduce

```bash
pnpm install
pnpm run worlds:build
pnpm build

# 1) mock conformance: 22/22 for both worlds
pnpm test:p0

# 2) live node protocol: strict CA verification, real tokens
node scripts/live-conformance.mjs

# 3) live browser E2E: real UI confirmation, 10 jumps + rollback
P0_LIVE=1 node scripts/e2e-p0.mjs
```

The live fixture uses local certificates from `.p0-tls/` (generated by `scripts/tls-fixture.mjs`), Chrome host-resolver mapping for `alice.example` / `hana.example`, and **explicit SPKI pinning of the two fixture leaf keys**. It does not use `--ignore-certificate-errors`; the Node-side live suite validates the CA chain strictly. These `.example` origins and the 127.0.0.1 mapping are **test-only exceptions**.

## Mock vs live distinction

| Layer | Mock (`packages/check`) | Live (`scripts/live-conformance.mjs`) | Live browser (`scripts/e2e-p0.mjs`) |
|---|---|---|---|
| Handshake state machine / error codes | yes (22 cases) | token issue/consume/replay/expiry/wrong-world/unreachable/timeout/trust mismatch | real UI confirm + traversal |
| Descriptor signature / trust anchor | unit-level ed25519/JCS | signed descriptors + pinned keys | WebCrypto verification in-browser |
| Prefetch budget / sync whitelist | unit-level | — | runtime `prefetchTest` / `tryWritePointer` |
| Rollback | unit-level | — | node B killed, source state preserved |

The 22 mock cases are retained as fast unit tests; the live suites are separate and report independently. **Do not read "22/22" as "22 live cases".**

## Security / trust notes for this phase

- Fixture node keys and TLS CA are generated at test time and are **not** production identity; `trust.json` is an out-of-band pin for the fixture only.
- Production runtime still blocks public world links to localhost/private networks; only the explicit `.example` fixture is allowed via test trust anchors (SSRF / DNS-rebinding guard).
- The node issues opaque one-time tokens bound to target world + session + nonce + expiry; it does not yet implement rate limiting, quotas, or key rotation.

## Remaining P0-2/P0-3/P0-4 gaps

1. **P0-2** — add node-side rate limiting/key rotation; one-click node launch on a clean machine; record cold/warm on a real desktop (not SwiftShader).
2. **P0-3** — bind the remaining mock conformance cases to the real node/runtime where possible; publish a single live conformance report format.
3. **P0-4** — external reproduction by a developer not involved in the project (issue form exists); then freeze SHP v0.1 and evaluate G0.
